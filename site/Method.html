How it’s built. Where the data comes from, and what it gets wrong.

Where the data comes from

  • enforcementtracker.com, provided by CMS: fines published by European data protection authorities.
  • GDPRhub, run by noyb: decisions with and without fines, with short English summaries.

Both are licensed CC BY-NC-SA 4.0, so Pharos uses the same licence: you can reuse the data for non-commercial purposes if you credit the sources. The summaries are the sources’ own text.

How it’s put together

A script I run collects both sources into a SQL database (SQLite) and exports it to this site. Along the way it:

  • keeps dates only as precise as the source gives them (a day, a month or a year);
  • stores a fine as a number only when the source gives one clear amount in euro;
  • spots the same decision appearing in both sources and shows it once, without deleting either record;
  • groups decisions by the GDPR articles they cite, so you can find, for example, all Article 32 cases;
  • logs every run, so I can see what changed and when.

Each decision gets an ID like 2026/IT/108 (year, country, number) that won’t change.

What it gets wrong

  • Some duplicates slip through. Decisions without a fine are hard to match between sources.
  • Two different decisions from the same country, in the same month, with exactly the same fine could be mistaken for one. It’s rare.
  • Fines in other currencies, or described in words (“reduced from 24,000 to 22,000”), are shown as written but left out of the totals.
  • The categories (“Data security”, “Consent”…) come from simple rules, not from reading each decision. Use them as filters, not conclusions.
  • Pharos only knows what its two sources know, and not every case has a summary yet.
  • Amounts are as reported, and may not reflect later appeals.
